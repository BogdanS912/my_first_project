1 Три области: рабочая папка — реальные файлы на диске, которые вы редактируете; индекс (staging area) — промежуточная область, куда изменения попадают после git add, это «черновик» будущего коммита; репозиторий — хранилище зафиксированных версий (коммитов) в папке .git. Отличие: рабочая папка — текущее состояние файлов, индекс — подготовленные к коммиту изменения, репозиторий — зафиксированная история версий.

2 git add — переносит изменения из рабочей папки в индекс, файлы начинают отслеживаться и попадают в черновик следующего коммита. git commit — фиксирует содержимое индекса в репозитории, создавая новый коммит с хешем, автором, датой и сообщением. git push — отправляет локальные коммиты в удалённый репозиторий, синхронизируя локальную ветку с удалённой.

3 Информативное сообщение объясняет, что и зачем изменено, а не просто «update». Это облегчает понимание истории проекта, помогает при откате, поиске багов и код-ревью, позволяет быстро найти нужное изменение через git log и формирует читаемую профессиональную историю.

4 git add имя_файла добавляет в индекс только указанный файл (точечный контроль). git add . добавляет все изменения в текущей папке и подпапках. Первый вариант — когда нужно закоммитить только конкретные изменения, второй — когда все изменения относятся к одной задаче.

5 git status показывает состояние рабочей папки и индекса относительно последнего коммита. До git add файлы отображаются как untracked или modified в разделе «Changes not staged for commit»; после git add переходят в «Changes to be committed»; после git commit рабочая папка чистая — «nothing to commit, working tree clean». Также показывается ветка и её состояние относительно удалённой.

6 Команда связывает локальный репозиторий с удалённым по указанному URL и присваивает ему имя-псевдоним. «origin» — общепринятое имя для основного удалённого репозитория (стандарт де-факто, технически можно назвать иначе).

7 Флаг -u (--set-upstream) связывает локальную ветку main с удалённой origin/main. После этого можно использовать просто git push и git pull без указания удалённого репозитория и ветки — Git запомнит связь.

8 Ветка по умолчанию — основная ветка, с которой начинается работа и куда обычно вливаются изменения. Исторически Git создавал master, но сейчас GitHub и многие инструменты используют main; в моём репозитории создалась ветка main. Это важно, потому что имя ветки влияет на команды (git push origin main vs master), настройки CI/CD и совместную работу — несовпадение имён вызывает ошибки и путаницу.

9 История просматривается командой git log (или git log --oneline, git log --graph). Для каждого коммита видно: хеш, автора (имя и email), дату и время, сообщение коммита, а с флагом --stat — изменённые файлы.

10 Изменения не попадут в коммит, потому что git commit фиксирует только содержимое индекса. Если индекс пуст, Git сообщит «nothing to commit» (или зафиксирует только ранее добавленные файлы). Изменённый файл останется в рабочей папке как modified и будет отображаться в git status в разделе «Changes not staged for commit».
